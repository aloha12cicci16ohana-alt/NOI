# ケーススタディ：作り方テンプレートと実例ドラフト

ポートフォリオで「画像羅列だけ」から脱却するためのケーススタディの書き方と、実際の素案2本。

---

## なぜケーススタディが必要か

発注側の心理：
- 「キレイ」より「課題を解決した実績」を見たい
- 「自社の悩みと似ているか」を判断したい
- 「この人に頼んだら、こういう価値が得られる」を予測したい

画像だけだと「キレイなサイトを作れる人」止まり。
ケーススタディがあると「ビジネス課題を理解して設計できる人」に格上げされ、単価が上がります。

---

## ケーススタディの型（5項目）

すべての案件をこの順番で書く。長さは1案件あたり 500〜800文字 が目安。

| 見出し | 書くこと | 文字数目安 |
| --- | --- | --- |
| ❶ クライアント／業界 | 業種・規模・依頼の経緯 | 80字 |
| ❷ 課題（Before） | 何に困っていたか、数値で言える事実 | 150字 |
| ❸ 提案・設計の考え方 | どこに着目し、何を優先したか | 200字 |
| ❹ 実装内容 | デザイン／実装で具体的にやったこと、使った技術 | 150字 |
| ❺ 成果（After）／引き継いだ運用 | 数値・お客様の声・運用方法 | 150字 |

## 実例ドラフト①：株式会社 賢工務店｜ECサイト構築

ポートフォリオに掲載するときの本文（そのまま貼ってOK）。

### CASE STUDY 01｜株式会社 賢工務店

**業界**：工務店／建材EC　　**期間**：2026年1月〜2月　　**役割**：ディレクション・デザイン・実装（一人完結）

#### 課題（Before）

賢工務店様は自社で取り扱う建材・住宅関連商品を、既存の問い合わせ＋FAX注文の体制で販売されていました。「商品ラインナップは充実しているのに、Web経由の購入導線がない」「カタログPDFを送るたびに営業の手間が増える」という課題があり、ECサイトの新規立ち上げをご相談いただきました。

#### 提案・設計の考え方

ECサイト構築では、**「商品の見せ方」より「営業の手間を減らす受発注フロー」を先に設計する**ことを優先しました。工務店業界の購入者は、価格・スペック・納期を比較するシーンが多く、購入前後のやり取りが煩雑になりがちです。そこで「商品カテゴリ→詳細→決済→自動メール」の標準フローと、「個別見積が必要な大型商品」の問い合わせ分岐を併存させる構成にしました。

#### 実装内容

WordPress＋WooCommerceで構築。商品カテゴリ・タグ・属性設計、決済設定（クレジット／銀行振込）、受注後の自動メール、在庫管理、配送方法の組合せ設定を実装。WordPressテーマはカスタマイズ余地を残したものを採用し、Functions.phpで一部の表示制御を追加。

#### 成果・引き継ぎ

サイト公開後、社内の運用者が商品登録・受注確認・配送設定を自走できるよう、運用マニュアルを作成して引き渡しました。「電話とFAXに割いていた時間を減らせる」「Webからの新規問い合わせが増えた」というフィードバックをいただいています。

**使用技術**：WordPress, WooCommerce, Functions.phpカスタマイズ, Photoshop, Illustrator
**URL**：[https://ken-support.jp/](https://ken-support.jp/)

## 実例ドラフト②：株式会社うなぎの兼光｜HPリニューアル

---

### CASE STUDY 02｜株式会社うなぎの兼光

**業界**：老舗うなぎ専門店／飲食　　**期間**：2020年3月〜5月　　**役割**：ディレクション・デザイン・実装（一人完結）

#### 課題（Before）

老舗うなぎ専門店として地域で愛されているうなぎの兼光様。旧サイトはスマートフォンでの閲覧最適化が不十分で、「店舗の魅力（職人技・素材へのこだわり・歴史）が画面の小ささに負けてしまっている」状態でした。ブランドの世界観を、現代の閲覧環境（スマホ中心）でも崩さずに伝えるリニューアルが必要でした。

#### 提案・設計の考え方

「老舗らしさ」と「Webとしての読みやすさ」を両立させるため、**ファーストビューに職人技の写真と”一文だけの強いコピー”を置く構成**を採用しました。料理写真をスクロールに合わせて段階的に見せ、読み手が「お腹が減る」「お店に行きたい」と感じる順序を意図的に作っています。

#### 実装内容

WordPress＋Swellテーマで構築。Swellの標準機能で実現できない一部表示制御は Functions.php をカスタマイズして対応。Photoshop／Illustrator／Canva／Figma を組み合わせて素材制作を行い、サーバー取得・Google Search Console・Google Analytics 4 の導入・初期計測設定まで担当しました。

#### 成果・引き継ぎ

公開後の運用は店舗スタッフが自走できるよう、記事投稿マニュアルを納品。「写真の力が伝わるサイトになった」「スマホで見ても店の格が伝わる」とご評価いただきました。

**使用技術**：WordPress (Swell), Functions.php, Photoshop, Illustrator, Canva, Figma, GSC, GA4
**URL**：[https://unaginokanemitsu.jp/](https://unaginokanemitsu.jp/)

## 書く時のコツ

- **クライアント名・URL は「公開許可をもらった分だけ」掲載**。許可が取れていない案件は「業種｜飲食」のように匿名化してOK。
- **数値が出せない案件は無理に数字を入れない**。代わりに「お客様の声」「運用上の改善」を入れる。
- **「私が」を主語にしすぎない**。「クライアントが自走できるよう」「導線が」を主語にする方が、読み手は事業視点を感じ取る。
- **AI活用を1〜2案件で軽く触れる**。全部に書くと「AIで作ってる人」に見える。1〜2件で「業務効率化のために組み込んでいる」程度に。

## ポートフォリオへの実装方法

GitHub Pages 上のWorksページ（works.html）に追加する構成案：

```
[Works ヘッダー]
└─ フィルター：すべて / コーポレート / EC / LP / ブランディング / ブライダル

[ケーススタディカード（タイル）]
  ├─ サムネイル画像
  ├─ クライアント名
  ├─ 業界タグ
  ├─ 一行コピー（課題サマリ）
  └─ "詳細を見る" → 詳細ページに遷移

[詳細ページ]
  上記の5項目を見出し付きで表示
  最後にCTAボタン（「同じような案件で相談する」→ お問い合わせフォーム）
```

## ブライダル特化を打ち出すなら

業界専門ページを別途用意するのが最も効果的：

```
[サイト構成案]
TOP
├─ ABOUT
├─ WORKS（一般のケーススタディ集）
├─ BRIDAL（ブライダル業界向け専門ページ）← New!
│   ├─ ウェディング業界での20年の実績
│   ├─ ブライダル特化サービスメニュー
│   ├─ ブライダル案件のケーススタディ
│   └─ ブライダル相談フォーム
├─ SKILL
└─ CONTACT
```

このBRIDALページが「業界特化No.1」というポジションを言葉と実績で示す場になります。
